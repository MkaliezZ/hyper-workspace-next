## 产品目标与用户

公司员工在同一个 AI IM 工作台中讨论项目、查找企业资料、安排日程、完成审批，并协作修改文档、表格和演示。讨论应沉淀为可继续修改的成果，实际业务动作应有可查询回执。产品管理员维护成员、项目、规则和共享模型连接。普通员工使用自己的来源权限，有权审批的人对自己的审批票负责。来源系统管理员与产品管理员分别管理各自权限。

界面主体采用蓝、白、黑，支持桌面和手机尺寸。聊天、项目上下文、任务、成果和执行状态相互可达。用户可查看依据、修改草稿、确认动作、停止执行，并在失败后核对结果再接续。

## 产品原则与固定架构

沿用 P01–P08 的目的、人机关系、主动尺度、成果可修改、方法复用、事实与执行有据和表达清楚要求，能力映射沿用 C00–C07，资产映射沿用 A01–A10。完整编号定义保存在冻结包。

React 和 TypeScript 实现前端，NestJS 实现业务后端，独立 Worker 处理执行任务，Docker Compose 管理服务。PostgreSQL 保存业务、权限、关系和回执，pgvector 保存可重建索引，pg-boss 管理后台队列。DSH 为默认执行器，Hermes 为必需的兼容执行器。人工入口和两个执行器共用业务服务。

Nextcloud Talk、Files/WebDAV 和 Calendar/CalDAV 提供消息、原文件与日历来源。来源原件保持权威，产品维护关联、派生资料、规则与回执。所有读取和写入都按当前员工身份、来源权限和版本重新检查。企业密钥只通过受限配置和产品凭据服务保存。

## 扩展顺序与功能要求

### 1. 日历排期

员工可查看本人及获准共享日历，按时区处理定时、全天、重复事件和单次例外。系统查询忙闲、合并冲突、给出候选时段，并在创建前复核候选是否仍可用。支持创建、修改、取消、会议邀请与参会回复，支持日程和项目或待办的私人关联。

验收需要真实 CalDAV 读写与撤权、版本冲突、写入超时后回读、邀请与取消状态、桌面和手机界面，以及 DSH/Hermes 共用业务服务的完整流程。原交接列出的有界整组会议改期和逐次参会回复现已实现并通过对应 CI；本机另用实际供应商检查建会、邀请回复和回读。重复系列/例外的适用范围及公司真实日程验收仍按 [日历](CALENDAR.md)逐项核对。

### 2. 复杂审批

管理员维护版本化流程与表单，支持条件分支、串行阶段、并行步骤和会签。申请人可提交、修改、撤回或退回重提。有权审批人执行同意、拒绝、退回和转交。催办应有冷却规则，所有动作可审计。在途申请使用提交时的流程版本，并正确处理并发和规则调整。

验收需要多主体状态机、事务和并发、越权拒绝、回执恢复、人工操作和双执行器入口。审批结论来源于获授权审批人的实际动作。详见 [审批](APPROVALS.md)。

### 3. 图片与扫描件 OCR

支持 PNG、JPEG、PDF 选页，保留原图或原页、文本块、表格、坐标、来源版本和识别引擎。提示缺失或低置信度，员工可校对并明确确认。确认版本可进入私人知识检索，语义索引由员工另行建立，撤权或原件变化清理派生内容。人工、DSH 和 Hermes 共用页识别和回执服务。

低成本主线已实现 RapidOCR + RapidLayout + RapidTable + ONNX Runtime CPU 服务。OXR 保留为有兼容 GPU 和适用授权时的候选。组件锁、来源与许可说明、模型摘要、资源测量和合成样本结果见 [OCR](OCR.md)。验收还要覆盖更多真实业务版式、低质量输入、失败保留和实际目标机容量。

### 4. 复杂表格与 Office 协作

同一办公内核支持 DOCX、XLSX、PPTX，提供多人编辑、评论、修订和版本。复杂表格需要公式重算、跨表引用、筛选、数据验证、透视和图表。AI 需要写作、改写和表格操作，两个执行器调用同一套 OfficeTools，服务端确定文件、范围、权限、版本和实际保存结果。

当前已有带来源权限和版本检查的统一打开入口、返回后的来源版本核对、Collabora/Nextcloud Office 固定版本及内网部署配置。原编辑器加载失败已修复，三格式实际编辑/保存、双人协作、评论与修订接受、活动会话撤权、保存冲突恢复、同核 OfficeTools 与可编辑副本均有当前仓库 CI 和本机实际验证。复杂表格的具体保真、命名表和 SUM 透视范围见[兼容记录](../runtime/office/COMPATIBILITY.md)，更复杂版式与公司文件按实际契约继续核对。详见 [Office](OFFICE.md)、[真实模型 Office](REAL-OFFICE-ACCEPTANCE.md)及[本机跨功能验收](LOCAL-PILOT-ACCEPTANCE.md)；原[交接问题](WINDOWS-HANDOFF.md)作为历史保留。

## 核心用户流程

1. 员工以企业账号登录，选择项目、消息、文件或日历的明确范围。
2. 人工或 AI 形成可检查的草稿、意图或操作计划，显示来源与需要确认的内容。
3. 产品后端核对当前身份、权限、规则、预算和来源版本，执行已授权动作。
4. 产品保存实际回执，来源写入后回读。结果不明时进入 recovery_required，再核对业务状态。
5. 员工修改成果、确认版本、追踪任务，或停止并在安全边界接续。取消后的已发生动作要依实际回执处理。

## 非功能与部署要求

- 权限与来源隔离覆盖读取、上下文构建、索引、模型调用和写入，私人资料向项目传播需要明确授权。
- 重试、并发和部分失败保持状态一致，审计事件可定位到版本、主体、Run 与来源。
- 公开仓库保存源码、依赖锁、迁移、测试、部署、中英双语 README 与贡献/许可范围说明，模型权重和依赖按固定来源另行准备。
- 公司正式环境为局域网 Linux 服务器，通过固定内网 IP 和内部 CA 的 HTTPS 访问。机器/IP 当前待准备。阿里杭州仅是技术试用环境。
- Windows 为接续开发端，本次建议在 WSL2 Linux 文件系统中运行开发依赖。Windows 原生运行的完整兼容性尚待验证。
