## 来源边界

`apps/api/src/providers/calendar.ts` 定义 CalendarProvider；`nextcloud-calendar.ts` 使用员工来源凭据和后端解析的 remote UID。日历路径限制在本人 CalDAV calendar-home，支持来源挂载到本人根下的共享日历；实际共享路径兼容性待真实 Nextcloud 验证。不使用模型指定身份、服务器或任意 URL。

PROPFIND 按 XML namespace 识别日历及当前读取/新增/修改/删除权限。REPORT 查询采用半开 UTC 时间窗口，单次最多 93 天、500 对象、2 MiB；单对象最多 256 KiB。不静默截断结果。返回完整 VCALENDAR，保留 VTIMEZONE、重复主事件/例外/EXDATE；REPORT 的 XML 换行规范化回 CRLF，GET 保留来源文本。原始查询不展开重复实例。新增 occurrences 查询将相同有界窗口交给来源 CalDAV expand，返回标记为 expanded 的只读表示；编辑前必须重新读取原始主事件。calendar-projection 将已展开事件转成日期/UTC 实例，缺失时区或浮动时间保持明确状态，不能偷偷采用服务器本地时区；来源未展开、反向时间、重复实例或超过1000实例则整体失败。忙闲查询同时核对原始日程与来源展开结果。详见下文。

GET 要求 ETag。创建使用 If-None-Match:*，替换/删除要求确切强 ETag；412 不覆盖他人更新。所有请求禁止重定向，来源 href 限定当前员工根与所选日历；XML DTD、重复关键属性、外部 URL、路径穿越及部分响应拒绝返回。

此 Provider 不自动重试写入。网络中断、重定向/5xx、非预期成功状态标记 CalendarDeliveryUnknown；调用方必须先持久化意图并按 UID/源版本/操作标记回读和对账，再形成业务回执。PUT 201/204 只代表来源接受，不能宣称完整动作成功。CalendarService 已接持久意图与回读；人工写接口与固定计划的AI业务入口已接通。

普通对象 PUT 暂拒绝 METHOD/ATTENDEE/ORGANIZER，避免绕过明确授权隐式发邀请；后续必须实现专用排期服务和真实邀请/取消/状态验收，这项保护不构成邀请功能已完成或永久取消。

## 产品业务与人工界面

- `CalendarService` 与 `calendar-codec`：创建 UTC 单次/全天事件；修改系列文字时保留所有 VTIMEZONE、RRULE/EXDATE 与实例例外；单次时间可改，重复时间调整留待专用规则编辑。参会事件暂拒绝普通修改/删除路径，专用邀请服务仍必须补齐。
- 044 保存私人主体、来源连接/UID、精确日历/对象/版本、请求键、结构化计划、期望内容/摘要、尝试状态与观察回执。准备不写来源；并发 apply 只有一个可领取，创建 If-None-Match、更新/删除 If-Match；主体/成员/来源权限在业务及事务边界重新检查。
- 只有源 UID、产品操作标记、完整语义摘要均一致才记录 matched；删除记录 absent，表示已核对不存在，不捏造删除动作归因。未知结果只核对，不重发；HTTP 明确拒绝记录失败。取消前未发出则 cancelled；已发生效果仍据实保存，同时显示停止请求。
- 桌面7列/手机单列周视图、新建/修改/删除、刷新、只读控制、时区标记、当前员工最近30条操作；未知回执刷新后仍可核对，已准备计划可再次查看后执行。所有标题/正文作为文本渲染。来源失权清理旧内容。
- 普通手动 API：GET `/api/calendar/calendars`、POST `/api/calendar/query`、GET/POST `/api/calendar/commands`、GET `/api/calendar/commands/:id`、POST `/:id/apply`（confirmed=true）、`/:id/reconcile`、`/:id/cancel`。身份来自登录，输入拒绝 actor/服务器/任意URL；DSH/Hermes共用该业务服务，不能绕过授权调用 Provider。
- 配置：Nextcloud 企业登录与成员组就绪后，`NEXTCLOUD_CALENDAR_ENABLED=true`；Compose API/Worker 共用开关。开发可用进程环境 `WEB_PORT`/`API_PORT` 启动隔离端口，Playwright 可指定 `HYPER_TEST_ORIGIN`；默认仍为5173/3100。

## 重复日程与单次例外

- 新建可选按天、周、月或年重复，间隔 1 至 12，总次数 2 至 104，含第一次。重复日程在五年内结束。定时日程支持明确的 IANA 时区，保存来源所需的时区定义与过渡，跨夏令时保持所选时区的开始时刻。遇到不存在或重复出现的墙上时间，要求员工改选。全天仍使用日期及排他的结束边界。 [iCalendar 重复规则](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.5.3)
- 从周视图选择“修改本次”或“取消本次”。后端先用有界来源展开结果核对当前对象、版本和原始实例标识，然后只更新该次例外。改期保留原 `RECURRENCE-ID`；取消使用 `EXDATE`，并移除同一次已移动的例外。其他实例和例外继续保留。来源时区无法核实或遇到 `RANGE` 例外时要求在来源日历处理。 [iCalendar 实例标识](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.4)
- 人工与 DSH/Hermes 继续走同一意图、权限、条件写入及回执。单次变更在命令和 AI 回执中区分修改与取消。整组重复规则调整见下文。

## 会议邀请、参会回复和取消

- 创建会议时从企业目录选择最多 12 名员工。后端在准备和提交时核对工作区、来源日历所有者、当前成员范围以及 Nextcloud 确认的唯一日历地址。只向所选日历提交条件写入。员工通过界面明确确认，DSH/Hermes 使用同一已准备的动作。地址留在服务端，模型和浏览器回执只拿员工标识和来源事实。 [CalDAV Scheduling](https://www.rfc-editor.org/rfc/rfc6638.html)
- 来源回执将保存、来源报告送达和员工回复分别记录。只有明确的来源本地送达状态才标记送达。来源未报告送达时界面保留未知。超时后只按原 UID、动作标记和来源状态核对，重试复用同一意图。
