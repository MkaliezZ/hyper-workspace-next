# 复杂审批工作台

在工作区导航选择“审批”。管理员可以发布流程或复制已发布定义并发布下一版。员工选择流程后创建私人草稿，填写当前版本的表单并确认提交。审批人只处理分派给本人的当前步骤。工作台记录每次提交、退回、审批、撤回、转交和催办。

## 流程和在途申请

- 迁移 049 将流程、已发布版本、申请和操作记录保存在产品 PostgreSQL。流程发布校验管理员角色、当前版本和指定员工。新申请选择当前发布版，已创建申请固定其版本。发布新版本时，在途申请及其表单定义保留原版。
- 表单支持文本、整数、布尔和枚举。条件引用同一表单的必填字段，可做相等、不等和整数范围判断。同一阶段中满足条件的步骤并行开始，每个步骤可要求一人、全员或指定人数同意。一个阶段的所有步骤通过后，下一阶段才可处理。
- 提交时固定本轮实际匹配的步骤、审批人和人数阈值。未匹配任何步骤、审批人离开工作区或申请人被列为本人审批人时，提交会停止。签署人明确确认同意、拒绝或退回。达到阈值的步骤结束，剩余票数不足时申请拒绝。退回后申请人可改表单并重新提交，本轮分派从头计算，历史意见进入审计。
- 申请人可撤回尚未结束的申请。当前审批人可将自己尚未处理的分派转交给另一位当前员工，转交后旧分派版本不能继续提交。申请人可向当前未处理员工发送产品内催办，同一申请、轮次、步骤与接收人间隔至少 30 分钟。接收人只会看到仍有权限处理的催办。

## 权限与回执

- 使用产品登录主体、当前工作区成员资格及现有来源身份校验。申请详情只对申请人和已启用阶段的审批人开放。退回重提时按本轮重新确定范围。管理员发布流程的权限独立于申请内容读取权限。
- 同一申请的变更持有数据库行锁。审批按轮次与分派版本校验，撤回和提交按申请版本校验。同一员工用相同键重试同一操作时返回原回执。转交后仍可用原键核对转交回执，当前申请权限按新分派计算。
- GET/POST `/api/approvals/flows` 管理版本，GET/POST `/api/approvals/requests` 列出或创建申请。GET `/api/approvals/requests/:id` 核对详情，POST `/api/approvals/requests/:id/actions` 执行明确动作。GET `/api/approvals/reminders` 查询本人当前催办。写入回执和审计同事务提交。
- 管理员可用可视化编辑器编排字段、条件、串行阶段和并行步骤，并选择审批人与同意阈值。高级 JSON 模式可导入或编辑同一格式。DSH/Hermes 共用审批操作入口与真实模型验收在后续批次实现。

## 升级与回退

本批对应 P01/P02/P03/P04/P05/P07/P08、C01/C03/C04/C05、A01/A02/A06/A08/A10 与 E01/E04/E07/E08/E09/E10 的审批子场景。停止旧 Worker 后备份数据库并执行 `npm run migrate`，随后启动同版本 API 与 Worker。回退时先停审批入口，归档已发布版本、在途申请、表单和操作记录，再恢复经验证的数据库和应用版本。审批记录保留实际决定与处理人。

## 本地验证

桌面与手机浏览器用三个合成身份调用真实 API 和 PostgreSQL。管理员发布、员工填写和提交申请、催办进入接收人列表、审批人确认同意、申请人刷新回读意见。手机确认界面已检查横向溢出。 [桌面工作台](images/approvals-desktop.png) · [手机确认审批](images/approvals-mobile.png)
可视化编辑器已用整数金额条件实际发布流程，员工从发布版本加载对应表单，命中分支后才开放审批。 [可视化配置](images/approval-builder.png)

本地 286 项 PostgreSQL/HTTP、99 项单元、全工作区类型与构建通过。新增数据库用例覆盖版本冻结、串并联与会签、退回和撤回、撤权、转交与催办、分支无审核时拒绝提交。真实 Nextcloud 的审批成员撤权与重新登录用例已纳入对应提交的 Actions。

来源撤权验证覆盖正在办理的审批。移除 Nextcloud 工作区组后，旧会话的签署被拒绝，申请版本保持原样。恢复来源组后，产品仍要求管理员恢复工作区成员资格，员工随后重新登录并确认签署。
