# Office 结构化编辑与新副本回执

Office Tools 在当前员工的 Nextcloud 来源权限内检查 DOCX、XLSX、PPTX，保存可修改提案，再由明确确认的提案版本生成新的可编辑副本。人工入口和 DSH/Hermes 调用同一个 `OfficeService`。真实引擎能力、业务协议测试、模型端到端、公司安装分别验收；本功能不会把生成文字当成源文件写入成功。

## 服务接口与证据

`inspect(subject, source)` 绑定员工来源身份、文件 ID、路径、ETag、大小、MIME、SHA256，返回同核检查的可编辑目标。`checkSource` 用于运行期间的轻量权限/版本检查，不调用引擎。

`create` 绑定来源 SHA256、固定结构化操作、目标目录和幂等键。`edit` 要求预期 revision；两者都实际调用引擎变换/重开校验后保存操作和预览，不上传文件。预览包含每项操作的目标、修改前/后值、重算标记、剩余公式错误和重开验证结果。替换文字会改变所选段落/shape 的行内格式，不承诺所有 OOXML 对象的无损往返。

`apply` 要求 `confirmed:true`、预期 revision 和幂等键。执行重新下载并核对源 SHA，再生成输出；在 PUT 之前持久化确定的目标路径、输出 SHA256、大小、来源版本和尝试标识。再次检查当前成员、员工凭据、来源读取权、目录创建权、revision 与运行 guard 后，仅发送一次 `If-None-Match:*` PUT。新名称为原文件名片段加提案 UUID，不覆盖原件或撞名目标。成功回执来自员工身份下 GET 字节 hash 与再次 stat 的 ID/ETag/大小一致结果。

状态为 `prepared → processing → applying → succeeded`。内部生成失败可重试，且需新幂等键；同一键返回原请求回执。发生或可能发生外部 PUT 后进入 `recovery_required`，只能 `reconcile` 读取对账，不能自动再发 PUT。412 撞名是不可重试失败，不把现存文件认作本次写入。取消生成阶段阻止后续写入；写入已开始时仅记录取消请求，仍按实际源证据保留成功或未知结果。进程失联后，120 秒过期的生成允许新尝试；过期写入只允许对账。

源与数据库不能构成一个分布式事务，权限与版本在最后一次检查之后仍可能被外部系统改变。最终条件 PUT 始终由当前员工凭据发送，未知结果保留为待核对事实，不做补偿删除。

## 权限、隐私与执行边界

每次查询 proposal、预览、操作或输出都重新检查当前成员/凭据/来源访问。跨员工 ID 返回 404。来源撤权或漂移会清空保存的操作、预览、标题、路径、输出文件元数据与请求快照；保留 ID、版本/hash、状态和时间等审计字段。已生成的真实文件不删除，界面显示来源失效；已失效提案不能恢复执行，应重新选择来源创建。

目标目录来自当前员工 WebDAV 命名空间，`oc:permissions` 必须包含 `C`，实际创建权限仍由条件 PUT 强制执行。运行时地址只由管理员配置 `HYPER_OFFICE_BATCH_URL`，仅接受内网 HTTP(S) 地址；无员工凭据、源 URL 或文件路径进入批处理引擎。协议和引擎版本固定，响应限长，输出 hash、重开标记与操作摘要校验后才进入应用流程。运行时另负责受限公式、ZIP/宏/链接/脚本防护，见 `runtime/office/PROTOCOL.md`。

`OfficeExecution` 的 `runId`、事务内 guard 和 signal 由可信宿主传入，核心在业务写入事务和 PUT 前调用 guard。源失效清理和未知副作用记账是单调安全操作，即使员工权限/运行租约已撤销也会执行，不会发起新的源写入。每次 create/apply 的 `cw_office_requests.run_id` 保留关联，避免新尝试覆盖旧执行回执；快照读取仍须先通过核心当前授权。

## 追溯、升级与回退

| 基线            | 本次实现                                                         |
| --------------- | ---------------------------------------------------------------- |
| P04 / C02       | 当前成员、来源身份、readBinary 和目标目录权限；运行 Policy guard |
| P05 / C04 / A04 | 人工可改提案，DSH/Hermes 共用相同操作合同和业务服务              |
| P07 / C05 / A08 | 原件保留、新副本回读、持久幂等与未知结果对账                     |
| A10             | 有界源读取、固定引擎协议、来源失效清理及审计保留                 |

迁移 `054_office_tools.sql` 新建提案和请求表，添加 `cw_runs.office_plan` 与 Office 工作流约束；不改现有来源文件或 OCR 资料。按部署程序先备份数据库、迁移，再重新运行 `scripts/deploy-database.mjs` 更新运行角色的新表权限。批处理服务按专用内网部署，API/Worker 的服务 URL 必须可达。

回退前停止创建/确认 Office 提案和相关 Worker，记录 `processing/applying/recovery_required` 条目；先对账已发生的源写入，不删除输出文件。优先回退应用与关闭功能入口而保留新表/审计字段。不能把只回滚应用当成未发生源副作用。若确需撤销 schema，应使用迁移前备份在隔离库演练，明确保留或导出已产生提案/回执与 Office runs 后再恢复；禁止直接删除尚待对账的记录。

业务集成测试使用合成 DAV/引擎协议和隔离 `*_test` 库，覆盖幂等、并发、撤权、版本漂移、取消、写入不明及回读。真实内核往返和真实模型执行需要各自运行时测试，不由合成协议测试代替。

实际 DeepSeek + DSH/Hermes 已完成六组三格式新副本检查，首轮不完整方案、13 次供应商请求与一条部分用量分别保留，见 [真实模型记录](REAL-OFFICE-ACCEPTANCE.md)。自动起草使用检查结果中的可编辑位置；检查范围之外的单元格不作为已验证的模型能力。具体工作簿、透视表及标题兼容限制见 [同核兼容记录](../runtime/office/COMPATIBILITY.md)。
